## ⚠ Warning (read this before touching a course whose novelty report lists `ai-scenario`)

**The archive of an AI-scenario course is NOT complete and NOT importable as an
equivalent course, even though the export reported `complete: true`.** The block
is a POINTER: its `scenarioId` (UUID) references a document in a separate,
never-captured Articulate service (the same pattern as `mondrian/mondrian` →
mondrian-api, see `rise-api-reference.md` §8a/§8b). Nothing in the course JSON
holds the character, dialogue, goals, passing threshold or scoring. The
`ai-scenario/ai-scenario` variant was surfaced only by the novelty report
(`new-variant`, 30 fields) — the generic cross-ref scanner did NOT abort,
because `scenarioId` is a bare UUID under a field name it does not know
(`core/census/scan.ts` knows Storyline media, `DRAW_FROM_QUESTION_BANK` and
`blockumentId` only).

Importing such a course today would (a) POST `type: "scenario"` on the course
create call with unknown shell semantics, and (b) ship the SOURCE `scenarioId`
verbatim. Read-back asserts media keys only, so the course would be marked
`imported` while the block renders "This scenario isn't available yet" /
"Invalid scenario" — or, if preview/publish boot resolves scenario ids
server-side as it does blockuments, 404s the whole course. **Do not import
these courses until the TODO below is done; treat them as manual-consultation
items.** Nobody is expected to migrate AI scenarios yet (2026-09-13 decision).

## What the course actually is

Two novelties at once:

1. **A new COURSE type.** `course.type: "scenario"` (previously seen: `null`,
   `onePage`, `aiOutline`), `course.metadata.createdVia: "ai"`,
   `lesson.metadata.createdVia: "ai"`, `lesson.settings.isGeneratingAIContent`.
   One titleless `blocks` lesson holding exactly one block. Feature-flagged in
   the runtime (`rise-lx-team-ai-scenarios-enable`,
   `experiment-business-creator-ai-scenario` in the 2026-06-23 capture); not in
   Articulate's public Q1/Q2 2026 release notes as of 2026-09-13.
2. **A new BLOCK that carries no content.** Full shape:

```json
{
  "id": "<uuid>", "type": "interactive", "family": "ai-scenario", "variant": "ai-scenario",
  "settings": { "v": 2, "paddingTop": 3, "paddingBottom": 3, "paddingLinked": true,
                "backgroundType": "IMAGE", "markerColorContrast": "AUTO", "snippetColorContrast": "AUTO" },
  "background": { "media": { "image": { "key": "rise/courses/<cid>/….jpg", "crushedKey": "rise/courses/<cid>/….jpg",
                "useCrushedKey": true, "type": "image", "alpha": 0.5,
                "dimensions": { "originalWidth": 1344, "originalHeight": 756 },
                "originalUrl": "stock-image.jpg", "sourcedFrom": "AI",
                "aiImageGenSettings": { "prompt": "…", "orientation": "landscape" } } } },
  "scenarioId": "<uuid>",          // ⚠ CROSS-ACCOUNT REF into an uncaptured service
```

   The background image (original + crushed) IS an ordinary uploaded course
   asset and was archived correctly (2 keys, manifest complete). `sourcedFrom:

   `image/text aside` in the same novelty report — provenance metadata,
   copy-faithful.

## What the player does (from the label sets, English)

A chat with a **Character** where the learner picks from **Response options**
("Choose the best response…", "Submit response"), numbered **Goals** ("Goal #")
scored *achieved / partially correct / not achieved*, a **Passing** threshold
("You met or exceeded / did not reach the passing threshold"), **Your score**,
**Retry scenario**, wrap-up ("That's a wrap—see how you did"). Two states only
make sense for an EXTERNAL, asynchronously prepared document: *"This scenario
isn't available yet — check back soon, it may still be getting set up"* and
*"Invalid scenario — the scenario has validation errors and cannot be
played"*. Unknown: whether character turns are stored in the document or
generated by an LLM at play time (decides whether a migrated scenario even
works on a plane without the AI feature).

Related novelties in the same document: `translationUpdates.aiScenarioUpdates
{count, locales}` (separate translation subsystem, sibling of
`mondrianUpdates`; already ignored by `core/l10n/updates.ts`), author
permissions `scenario_block:create` / `scenario_block:edit` (distinct from the
classic `branching_scenario_block:edit` = `interactive-fullscreen/scenario`,
which stays copy-faithful and unaffected), runtime bundle pin `ai_scenario`
(already in `core/storyline/build-request.ts`).
