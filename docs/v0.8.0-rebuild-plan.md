# v0.8.0 rebuild and certification plan

**Updated:** 2026-08-14
**Branch:** `codex/v0.8.0-rebuild`
**Status:** implementation complete; automated and live certification remain

## Release boundary

The rebuild is intentionally split into two releases.

### v0.8.0 — format foundation and product shell

- Four side-panel actions: Export from Rise, Import into Rise, Save course to
  document, and Launch Rise Creator.
- Rise Creator is a local-only page in a separate extension tab.
- Both existing DOCX flavors remain in the side panel; Creator does not duplicate
  them.
- One versioned local archive contract is used by Rise export and Creator.
- Strict v1 validation plus a warning-bearing legacy reader.
- A provider-neutral Course Blueprint between source interpretation and Rise
  JSON.
- A registry-backed deterministic compiler with donor provenance and verification
  state.
- Existing INTEA conversion routed through `PlannedCourse -> CourseBlueprint ->
  compiler`.
- Creator build lock and one-source-file/one-course package writer.
- A characterization fixture protecting the exact existing import write order.
- No cosmetic refactor of the proven import plan/executor/background.

### v0.9.0 — behavior-preserving maintainability refactor

Only after v0.8.0 is live-certified:

- split large side-panel state/UI modules;
- split background services behind the existing message protocol;
- split `core/import/plan.ts`, `core/import/executor.ts`, and the import
  orchestrator behind stable facades;
- expand the characterization corpus before each split;
- consolidate other modules when a feature, defect, or measured maintenance
  problem requires it.

File length alone is not authorization to rewrite the high-risk migration state
machine.

## Product and operating decisions

- This is an internal operator tool. Implemented functionality is exposed and
  tested immediately.
- “Safety” means Rise-format fidelity, loud failures, reliable local files, and
  regression protection. Creator needs no authentication or sandbox.
- Creator reads local input and writes local JSON/assets. It never contacts Rise.
- Folder emptiness is an operator rule. Creator does not scan or block a
  non-empty folder.
- One source file creates one course. The current deterministic v0.8.0 page
  handles one file/build; batch selection is a later UI addition.
- All live Rise creation goes through the standard side-panel importer.
- Rise payloads are captured or donor-backed; they are never guessed by code or
  an LLM.
- General AI conversion is deferred. Its design is in
  `docs/creator-ai-design.md`.

## Required product surface

The side-panel home contains exactly four primary actions:

1. **Export from Rise** — save courses, banks, assets, and account data.
2. **Import into Rise** — rebuild a validated local archive.
3. **Save course to document** — select prose DOCX or storyboard DOCX.
4. **Launch Rise Creator** — open the creator-only page in a new tab.

Rise Creator currently provides the deterministic INTEA storyboard path:

1. select the operator-prepared output folder;
2. select one source DOCX;
3. review recognized blocks, source provenance, unresolved rows, placeholders,
   and registry warnings;
4. acknowledge unresolved rows;
5. compile and write a standard ready-to-import package;
6. open the side panel and import through the normal course step.

## Architectural boundary

```text
Rise export --------------------+
                                |
INTEA parser -> Course Blueprint+--> versioned local archive
                                |              |
future AI -> Course Blueprint --+              v
                                         standard Import
                                               |
                                captured, paced Rise writes
                                               |
                                      GET_COURSE read-back
```

There is one route into Rise and one owner for each responsibility:

- export: Rise -> local archive;
- Creator: source file -> Course Blueprint -> local archive;
- import: local archive -> Rise;
- document export: local archive -> DOCX.

## Local archive v1

The root `manifest.json` carries:

- `format: "rise-local-archive"`;
- `formatVersion: 1`;
- `state: "building" | "ready"`;
- `origin: "rise-export" | "creator"`;
- creation time and tool version;
- course id/title/type, canonical path, and SHA-256;
- asset-manifest path and SHA-256 when present;
- source-account identity for Rise exports;
- compiler-registry revision and Creator summary for Creator packages.

The v1 inspector verifies before import:

- manifest version, shape, state, and duplicate ids;
- every course file, JSON shape, id, and checksum;
- every declared asset manifest and checksum;
- every asset byte file and checksum;
- every uploaded-media reference is backed by bytes or an explicit terminal
  failure.

Corrupt manifests are invalid, never treated as empty. A folder without a v1
manifest is read by the legacy adapter only when it contains readable course
files, and the UI displays the missing-integrity warning.

The importer performs this inspection before target pinning, authentication, or
network work. A v1 archive is importable only in `ready` state.

### Export readiness

Export writes `state: "building"` after the selected courses are fetched. The
asset stage rebuilds course/asset checksums and promotes the manifest to `ready`
only when the asset summary is complete. This makes the previously separate
“Download assets” requirement machine-visible.

### Creator write transaction

Creator does not merge archives. It:

1. checks for `_creator/build.lock` and warns, but does not block;
2. writes/replaces the lock;
3. writes the course;
4. writes a v1 `building` manifest;
5. writes blueprint and production artifacts under `_creator/`;
6. writes the v1 `ready` manifest last;
7. removes the lock only after success.

An interrupted build therefore remains visibly marked. Selecting/cleaning the
folder remains the operator's responsibility.

## Course Blueprint and compiler

`CourseBlueprint` is the only synthesis input. It contains:

- version and source metadata;
- course title and ordered lessons;
- a closed semantic block-intent union;
- human-readable source provenance per block;
- warnings/unresolved items;
- production-only narration;
- typed package-local asset references.

It contains no Rise family/variant payload, authoring envelope, donor settings,
or media key. The deterministic compiler owns those details.

The existing INTEA parser now uses this explicit route:

```text
DOCX -> PlannedCourse -> CourseBlueprint -> deterministic compiler
```

The later LLM path will stop at the same blueprint boundary.

### Local asset invariant

The canonical blueprint asset reference is an object with
`kind: "local-asset"` and a package path. It is valid only before compilation.
The compiler, executor final check, and live GET_COURSE read-back all scan for
this typed reference. Any surviving reference is a hard failure. The v0.8.0
compiler deliberately refuses blueprints with local assets until a captured,
registry-backed media adapter is implemented.

## Rise template registry

Every enabled semantic intent has:

- documented donor provenance;
- emitted Rise family/variant list;
- captured or derived donor confidence;
- compiler-test status;
- independent live-verification status;
- an optional warning/note.

Shipping bar for v0.8.0: documented donor plus compiler test. A template retains
a preview warning until it is marked live-verified. The derived empty-video
donor remains enabled for internal testing with a loud warning; the pilot decides
whether it becomes live-verified or is replaced by a proven text placeholder.

The compiler refuses disabled/unregistered intents and never asks an LLM to
invent Rise JSON.

## Regression strategy

The 0.7.0 suite is the regression floor, not the only proof.

Automated protection added in v0.8.0:

- valid, incomplete, corrupt, tampered, asset-bearing, and legacy archive
  fixtures;
- registry coverage and warning tests;
- INTEA-to-blueprint provenance tests;
- deterministic compiler/block donor tests;
- typed local-asset elimination tests;
- Creator building/ready/lock transition tests;
- an exact ordered-envelope characterization fixture for the canonical image
  course, including request bodies and S3 upload placement;
- all existing plan/executor/localization/Storyline/bank/fidelity tests.

No plan/executor split may begin until the characterization corpus covers the
specific behavior being moved.

## Live certification matrix

The internal operator owns execution because the accounts and visual inspection
require their authenticated Rise sessions. Codex prepares the build, checklist,
and report locations and triages every mismatch.

- Accounts: dedicated US and EU test accounts, never production customer
  accounts.
- Estimated operator time: 4-6 hours for the full two-plane matrix, plus triage.
- Evidence: saved import report, GET_COURSE read-back, exact manual-work list,
  and a short visual result note per scenario.

Scenarios on both planes where applicable:

1. regular course;
2. one-page course;
3. image/audio/video course;
4. question bank/draw block;
5. multi-language stack;
6. Storyline/Mighty;
7. folders and custom fonts;
8. Stop and resume;
9. source/target guard and target pin;
10. Creator-generated INTEA course, including each registry intent and the empty
    video warning.

Both DOCX formats are also opened in Word and LibreOffice for representative
simple, media-heavy, localized, assessment, and unknown-block courses.

## Release/rollback

- Preserve the last 0.7.x release tag/branch as the operational rollback while
  0.8.0 is certified.
- Build and load 0.8.0 unpacked alongside the rollback package with separate
  test folders.
- Do not rewrite old archives during read or preflight.
- A failed v0.8.0 live scenario blocks release; the operator continues using the
  0.7.x build while the issue is fixed on this branch.

## v0.8.0 definition of done

- Four requested side-panel actions and creator-only page are present.
- Both DOCX formats remain functional in the side panel.
- Rise export and Creator produce v1 manifests.
- Legacy archives remain readable with a warning and no mutation.
- Invalid/incomplete v1 packages are blocked before network work.
- INTEA conversion passes through Course Blueprint.
- Every enabled block intent has registry provenance and compiler tests.
- Local asset refs cannot silently reach Rise JSON.
- Creator writes one-course packages with an interrupted-build marker.
- The existing import state machine is not cosmetically refactored.
- Compile, full automated suite, and production build pass.
- The named live matrix is completed with evidence before release distribution.

## Deferred

- Generic AI provider pipeline and arbitrary PPTX/DOCX/PDF conversion.
- Provider-returned binary asset handling and registry-backed local-media adapter.
- Multi-file Creator batch UI.
- Update-existing-course workflow.
- Cosmetic split of the five largest migration/UI modules (v0.9.0).
