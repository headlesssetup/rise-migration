## Batch 0 — F0 cross-plane token poisoning (safety class, land first)

Root cause recap: the sniffer captured a header **we ourselves attached**, keyed by
the request URL's plane, so an unpinned probe that borrowed the EU token for a US
request wrote Konstantin's bearer into the US slot.

1. `entrypoints/background.ts` — `onBeforeSendHeaders` listener (~L210): **never
   capture a value the extension attached.** Skip when the bearer equals a token
   already held in ANY plane slot and it is not already this plane's value (that
   combination only happens when we borrowed it — the SPA never sends another
   plane's token). Same-value re-captures stay a no-op as today.
2. `tokenFor(plane, strict)` (~L192): **delete the cross-plane fallback** — make it
   strict unconditionally for every request that carries a plane. An empty
   target-plane slot must BLOCK, not borrow:
   "No Rise token for the <PLANE> plane yet — open a course EDITOR tab on the
   target account (the dashboard does not rotate the bearer), then retry."
   `slotFor(null)` stays (there is no request without a plane).
3. `GET_SESSION_STATE` (~L694): `hasToken` must use the strict lookup, so the panel
   reports "no target token" instead of a borrowed true.
4. Guard identity: **already correct** — `slotFor(plane)` reads the plane's own slot;
   it lied only because that slot was poisoned. No change beyond (1)–(3); but the
   guard's same-account copy gains the third explanation ("…or the target plane's
   token slot was filled from another plane — reload the target course editor").
5. F6 message improvement: on a `403` with a non-advancing token, say
   "open a course editor on the TARGET account" (`rawFetch` ~L416).

Tests: extend `entrypoints/sidepanel/orchestrator/import.pin.test.ts` + a new
background-level unit around the capture predicate (self-attached header ignored;
genuine SPA header captured; empty-slot request refused with the message).

## Batch 2 — F2 `onePage` shell lesson (UNBLOCKED — capture round 3)

New protocol fact: `POST /manage/api/content {type:"onePage"}` returns a course
that **already has one empty-titled `blocks` lesson**; we then created a second.

`capture_microlearning.mitm` (2026-08-04, see findings § capture round 3)
resolved the open question: **no rename envelope exists or is needed.** The US
editor never creates/updates/renames any lesson on a microlearning — all blocks
ride `CREATE_BLOCKS {lessonId:<shell lesson>}`, the title typing is course-level
(`UPDATE_COURSE_FIELD_THROTTLE`), and the lesson title stays `""` forever. Both
onePage sources in the archive (monolingual AND stack) likewise hold one lesson
with a plain `""` title — empty IS the faithful state.

- Executor: capture the handshake `GET_COURSE`'s existing lessons; if the shell
  holds an unclaimed empty lesson, the FIRST `create-lesson` step **adopts** it
  (`ids.set(sourceLessonId, shellLessonId)`, no CREATE) and the following
  `update-lesson` configures type/icon/settings as usual. Keyed on the observed
  doc, not on `courseType`, so an unexpected shell lesson on any type is handled
  too. The stack path's "create placeholder lesson" step becomes adoption the
  same way. No title write for the adopted lesson (faithful = empty).
- Side fact for F1/batch 4: on a onePage stack the lesson-1 title-ref pairing
  does not apply — the source lesson title is a plain `""`, not a ref.
- Docs: `rise-api-reference.md` §7 + `rise-import-protocol.md` §2 gain the
  "onePage shells ship with one pre-created lesson (title '', type blocks,
  position null); regular/aiOutline are lessonless; the editor writes blocks
  straight into it" facts.
- Tests: `executor.lifecycle.test.ts` — handshake doc with 1 lesson ⇒ no
  CREATE_LESSON for lesson 1, id map points at the shell lesson, exactly N lessons
  end up on the course.

## Batch 3 — F5 pending measured as a SET, not a count

`pendingChangesCount` is lazy (0 at read-back, populated hours later) and
`updateCount` is a segment-ish tally — both useless for comparison.

- New envelope: `GET /manage/api/content/{id}/translations/updates`
  (`core/import/envelopes.ts`), and a pure parser in `core/l10n/tables.ts`
  (or a new `core/l10n/updates.ts`) that flattens `courseUpdates` +
  `lessonItemUpdates` into a `Set<cellKey(l10nId, locale)>`, ignoring
  `mondrianUpdates` / `aiScenarioUpdates` (separate subsystems).
- Read-back (`orchestrator/import.ts` ~L1071): record the pending **set** in the
  report next to the predicted set, and compare sets — never counts. Keep
  `updateCount`/badge numbers as decorative context only.
- Report + log wording: the badge number is not the cell count; the SET is the
  truth. This also becomes the **acceptance instrument for batch 4** (expected
  pending set after idea 2 is tiny and known).
- Because the read is lazy, take it at read-back AND note in the report that a
  later manual check is authoritative; do not fail a course on a lazily-empty read.

## Batch 4 — idea 2: full default-language course, convert once (the rework)

### New stack sequence

1. Preflight — unchanged (locale codes vs `available-languages`; archived /
   row-less locale tables skipped + `flag-l10n-locale`).
2. Shell — `POST /manage/api/content` preserving `course.type`, GET_COURSE
   handshake, batch-2 shell-lesson adoption.
3. **Build the whole course in the DEFAULT LANGUAGE** from
   `materializeLocale(doc).doc`: real lesson titles (plain strings), blocks
   copy-faithful with fresh client ids, block/lesson media uploads, theme +
   typefaces, course images, bank binds, default-language storyline attach,
   provisional `!importing:` title. This is the **monolingual path** — the stack
   branch's own content machinery collapses into it.
4. **Convert once per formality group** — `POST …/translations`,
   `sourceLanguage` = the source's default locale. The AI now translates REAL
   content, and (the whole point) stamps `translatedAt` on every cell.
5. **Await** — poll `…/translations` to `complete`. Raise/parameterize the ceiling
   (240 polls ≈ 8 min was sized for minimal conversions) and keep per-poll
   progress; a full-course conversion's duration is unmeasured — record it.
6. **Pair refs** — new pure module `core/l10n/pair.ts`:
   `pairL10nRefs(sourceDoc, targetDoc, lessonIdMap)` walks both docs in parallel —
   course fields by key path, lessons by authoritative order (assert count/type),
   blocks by position within a lesson cross-checked against our minted block ids
   (assert `family/variant`), then a parallel walk inside each block — and returns
   `{map, sourceOnly, targetOnly}`. `sourceOnly` (source localized a field the
   target's conversion did not) ⇒ loud `l10n-ref` flag; `targetOnly` ⇒ EXPECTED
   when the source slot is absent/deep-empty (batch 1's F3 rule), else flagged.
   This module replaces "source l10nIds kept verbatim" everywhere.
7. **Per-locale table media uploads** — non-default locales only (default-locale
   media already rode step 3).
8. **Write TARGET-locale cells only**, batched ~20/envelope, one locale per
   envelope, media-remapped, addressed through the pairing map. **Never write a
   default row after the conversion** — that is the new write-order invariant (it
   would re-pend that cell in every locale under the US rule). Skipped: cells the
   source holds only in the default locale (media falls back = faithful; TEXT
   keeps AI text — reported), storyline cells, title/description.
9. **Storyline per language** — `copy_review_item` + the paired storyline cell per
   locale. ⚠ Unverified: whether the conversion l10n-ifies `media.storyline` at
   all. If the target field is a plain object rather than a ref, per-language
   storyline is impossible on that course ⇒ one shared bundle + a per-language
   flag. Detect and report; do not force a shape.
10. Per-locale label sets — unchanged.
11. **LAST: `set-stack-titles`** — clean title + description cells for **every
    target locale** (default first), fallback-resolved from the source. This is
    what removes the `!importing:` marker.
12. **Read-back** — unfiltered foreign-key scan + `verifyL10nParity` driven by the
    pairing map + structural/course-field parity + batch 3's **pending SET**,
    whose expected value is now exactly `{course title, course description} ×
    locales` (see decision D1) and nothing else.

### Decisions needed before this lands

- **D1 — the `!importing:` marker vs a zero badge.** Post-conversion, the title is
  a ref, so the clean title must be a CELL write, which bumps the default row and
  re-pends title+description in every locale (a 2-cell badge).
  **Recommended: keep the marker** (the partial-title safety invariant is worth a
  2-cell badge; the report states the expected set exactly). Alternative: write the
  clean title as a plain string just BEFORE the conversion → badge exactly 0 and
  "Update translation" becomes fully safe, at the cost of a crash after the
  conversion leaving a clean-titled partial.
- **D2 — fallback-locale title/description.** **Recommended: write them for ALL
  target locales** (as step 11 says) so no language visibly shows an AI'd
  `!importing:` string. This creates target TEXT rows the source lacks — accepted:
  text rows re-enter Rise's normal flag-and-retranslate workflow (the
  mirroring/disconnect objection is media-only).
