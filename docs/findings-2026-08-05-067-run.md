## G1 — REAL BUG (the only one): flagged storyline cells fail parity as `cell-changed`

Both PARTIALs are exactly one issue each: the announced, flagged,
deliberately-not-copied storyline cell EXISTS on the target (the conversion
minted it from the blanked block we shipped — `contentPrefix:""` vs the
source's `#media` token) and `verifyL10nParity` tolerates flagged storyline
cells only when ABSENT (`toleratedMissing`), not when present-but-divergent.
So a stack whose storyline could not be staged (unsubscribed source — the F8
Localize gate, expected!) can never read back `imported`.

Fix direction (small): the announced flagged-storyline cell ids tolerate
DIVERGENCE as well as absence — route `cell-changed` on those ids to
`expected` (detail preserved). The `l10n-storyline` manual-work flag already
carries the operator instruction; nothing becomes silent.

## G2 — pinned-tab NAVIGATION kills in-flight relays; the server may still process them

Timeline (capture): tab loads editor `/authoring/7nziPts…` 10:50:25 (fresh
bearer 10:50:27) → bank1 create POST 10:51:01 → **server 200** but the tab
navigated to `/manage/all-content` at 10:51:36 — the in-flight injected fetch
died with the page; the panel waited out the full 120 s rpc timeout → "FAILED
(HTTP 0)". Bank2 create 10:53:04: connection severed pre-response (mitm status
None) — **yet the bank exists** (the server processed it anyway). Tab back on
`/authoring/…` 10:53:13 → bank3 clean at 10:53:15.

Decisive evidence: the 10:53:15 LIST shows **all three banks** — "Newest
bank!" `au323qbrt1qv`, "bank 1" `lirh9kvhrvot`, "bank 2" `yqhq2c1dommj`. The
two "failed" ones each show 1 question = the shell's default starter question
(confirming capture-round-2's side observation that a fresh bank shell carries
one blank question; their real questions were never PUT).

Consequences:
- (a) The target holds two UNTRACKED shells; a naive banks re-run would create
  DUPLICATES. Operator: delete `au323qbrt1qv` + `lirh9kvhrvot` first.
- (b) The failure log swallowed the relay's error detail — `create failed
  (HTTP 0)` hides whether it was the rpc timeout (bank1) or a fast injection
  error (bank2). `cresp.error` held the answer both times.
- (c) The pin's plane check can't catch this: `/manage/all-content` is still
  the US plane, so relays proceeded into a navigating tab.

Fix directions:
1. Propagate the relay `error` text into every bank/course failure line (one
   line each in import-banks + executor logging).
2. HTTP-0 create reconciliation: snapshot the bank LIST at run start (the
   identity probe already fetches it), and on a status-0 create failure
   re-LIST and diff — a sole new bank with our exact title is ADOPTED

   id so the operator knows a shell may exist. Never blind-retry a status-0
   create (bank2 proves the server can process a request whose response died).
3. (Optional hardening) An `HTTP 0` from a pinned relay could trigger one
   paced re-check that the pinned tab is settled (`status === 'complete'`)
