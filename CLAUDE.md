# Rise Export/Import Tool — Project Memory

## What this is
Chrome extension (Manifest V3, Side Panel) that **exports** a Rise course (content + media) from one account and **rebuilds it editably** in another, via Rise's private "ducks" RPC + `manage/api`. Export and import are decoupled, independent phases. First business case: migrating courses from the Rise **US** server to the **EU** server.

**API & schema:** `docs/rise-api-reference.md` is the authoritative, captured protocol. Read it for endpoints/payloads/schema — never infer Rise's API from memory. The living **block catalog** is `docs/rise-block-catalog.md` (grown by novelty review — see invariants). Multi-language courses ("stacks") are captured + implemented per `docs/rise-multilang.md`. Also in `docs/`: `rise-migration-prd.md` (what/why), `rise-tool-build-plan.md` (how/sequence). Storyboard ⇄ Rise: `docs/rise-storyboard-plan.md` (SD docx → course) + `docs/rise-storyboard-format.md` (SBDOC: course → docx, the strict export format with identity tokens); the editing-protocol capture script (prerequisite for any update-existing-course work) is `docs/rise-capture-plan-editing.md`.

## Stack
- TypeScript; React (side panel); **WXT** (MV3 scaffold); Vitest.
- Model blocks as discriminated unions only where we transform them; everything else is copied verbatim.

## The core model: copy-faithful
Rise blocks **round-trip verbatim** — read each block's JSON and write it back unchanged via `CREATE_BLOCKS`. An unseen `family/variant` copies correctly with no per-type code. Only two things actually vary and need handling:
1. **Media keys** — download from `articulateusercontent.com/{key}`, re-upload to target (`GET_YURL` → S3 PUT → `CRUSH_IMAGE`/`TRANSCODE_ASSET` → `RESOLVE_ASSET`/`CHECK_STATUS`), and remap the key in the block.
2. **Cross-refs** — Storyline block → Review 360 item; draw-from-bank block → question-bank id.

## Invariants (never violate)
- **Strictly sequential, human-paced fetching AND writes.** Never parallelize course fetches, list pagination, or **authoring-API writes**. Wait for each request to fully finish before the next. ~2s delay with randomized jitter between courses, between pages, and between write envelopes (`CREATE_LESSON`/`CREATE_BLOCKS`/`UPDATE_*`/`GET_YURL`/`CRUSH`/`TRANSCODE`/locks). Look like a person, not a scraper. **Exception:** raw **asset byte transfers** are outside the pacing invariant — CDN downloads (public-read) and **S3 upload PUTs** (presigned) may run in a bounded parallel pool (~4), since they hit S3/CDN, not the authoring API. The ducks calls that bracket an upload stay paced.
- **Loud failure is scoped to media keys and cross-refs.** Run a generic recursive scan over the whole course document for media-key-shaped values (S3 keys, `rise/courses/{id}/…` and `rise/questionBanks/{id}/…` paths, `articulateusercontent.com` URLs) and cross-refs. If a media key or cross-ref is found that the remap plan does not cover, ABORT that course with the exact path + raw snippet. Do NOT abort merely because a block `family/variant` is unseen — copy it faithfully.
- **Novel shapes are never copied silently.** A new `family/variant`, a new field shape on a known variant, or a copy-faithful round-trip mismatch raises an alert classified as new-block / version-difference / our-bug, and requires an operator decision (per distinct shape, deduplicated + persisted). On accept it is recorded to the block catalog (`docs/rise-block-catalog.md`). Migration is not blocked, but nothing new passes unseen or undocumented.
- **Copy-faithful round-trip check.** For any block treated as copy-faithful, assert that re-serialized output equals source input except for intended media/ref remaps. A mismatch is a code-fault signal → alert, do not ship it silently.
- **No source media keys may survive** in an imported course. Assert every uploaded-asset key was re-uploaded and remapped before declaring success. (CDN URLs `cdn.articulate.com/...` and embeds YouTube/Vimeo are kept as-is — not re-uploaded.) A REQUIRED key that CANNOT be re-uploaded (active-media 403/404 at source, or an unsupported location) is **blanked and flagged**, never shipped as a source key. Capture-confirmed OPTIONAL authoring provenance (`inputKey` when playback has a distinct `key`, `media.tmp`, `originalImage`, and the unselected `key`/`crushedKey` image variant) is downloaded when available; if unavailable it is **blanked without a manual flag**, because it is not used to render the current course. A key is optional only when every occurrence is optional; one active occurrence promotes it to required. The final assertion runs **unfiltered** over the rebuilt doc (do not exempt flagged or optional keys; that once masked real survivors). The truth check is the **read-back**: `findForeignMediaKeys` over the actual `GET_COURSE` of the new course; survivors mark the course `partial`, never `imported`. A string may hold BOTH an embed and an uploaded key — classify by the key, and never blank a whole string when the key is embedded in authored HTML (strip the media reference, keep the text).
- **The source archive is the immutable source of truth.** Never mutate it. The target payload is derived at import time from a copy.
- **Built-in ("library") assets are copied, never re-uploaded and never re-hosted on faith.** Rise's own stock media appears as a host-RELATIVE key (`assets/rise/…`, resolved against the runtime's own plane) or an ABSOLUTE `cdn|images[.eu].articulate.com/assets/…` url. Both ship verbatim — including as course cover/card/logo (a course image with no *uploadable* key must NOT be treated as "no image"; that silently dropped sample-course covers). There is no account copy to move, and a region may lack an asset for licensing reasons, so re-uploading is the operator's call. Plane parity of the two libraries is UNVERIFIED: each distinct reference is HEAD-probed on the TARGET plane (public CDN, outside pacing, deduped + cached); absent/inconclusive → still shipped, plus a `builtin-asset` flag. Never rewrite a host without a passing probe. See `docs/rise-import-protocol.md`.
- **Storyline/Mighty: migrated end-to-end via Review 360 (Stage D), except known legacy packages.** Storyline blocks (and **Mighty**, which surfaces as storyline-variant blocks) are exported, repackaged, and re-uploaded: the source bundle comes from Rise's **web export** (ws-distributor `identify`/`build`/`package` on the plane's own host — a null plane is a loud error, never an EU default), `story.html` is converted from web-export to Review-360 manual-upload form (`core/storyline/repackage.ts` — the transform **asserts** its own output; an unknown package generation aborts that package loudly instead of shipping a broken one), and the zip is uploaded to the **TARGET** Review 360 over socket.io (`items:create` → presigned S3 PUT → `items:update` → `items:upload`, then poll for `contentPrefix`). Storyline export passes the current course id into bearer refresh, so a long dashboard-started run can boot a temporary inactive editor, rotate the token, and continue without operator intervention. Import attaches it via `copy_review_item` + a `media.storyline` patch. We only ever **CREATE** items in the target account — never delete or modify unrelated Review items, and never write to the **source** account's Review 360. Capture-confirmed Storyline 360 update 3.48 and earlier packages are classified as `legacy-unsupported`: extract them byte-faithfully from the web export into deterministic quarantined zips at `storyline-legacy/<courseId>/<leaf>.zip`, record `archiveZip` in the manifest/inventory report, and never upload or attach them (including stale pre-policy manifests). Resume must backfill a missing quarantined zip even when an older manifest exists, while preserving its modern upload records. Import replaces monolingual legacy blocks with a donor-backed visible text placeholder + manual-work flag. Missing/unfamiliar versions are never guessed legacy, and the modern automatic path is unchanged. (Stage D's modern path is operator-confirmed working. Upload currently rides a base64 `runtime.sendMessage` hop, so packages over ~48 MB fail a loud pre-flight size check; see `TODO(H5)` in `orchestrator/storyline.ts` for the panel-direct S3 PUT that lifts it.)
- **Auth: bearers are strictly PER PLANE — never borrowed, never self-sniffed (F0, capture-proven poisoning).** A request whose plane is known uses THAT plane's token slot or BLOCKS loudly — the old cross-plane fallback let an EU bearer ride a US request, and the webRequest sniffer then captured our own attached header back into the US slot, so every later "pinned" call carried the source account's credentials. The sniffer must never store a value already held in ANOTHER plane's slot (`core/auth/slots.ts`); the guard identity comes from the plane's own slot only. Bearer JWT (Okta), short-lived (~15 min) = the `_articulate_rise_` cookie value (claims `iss`/`cid`/`scp`); service worker attaches `Authorization: Bearer`. Re-auth on **`401` AND `403`** (authoring endpoints answer an expired token with `403 Forbidden`) and retry; refresh proactively near `exp` AND at run-start, **before each course**, and on a **heartbeat during a long course** (hundreds of paced writes outlast the token mid-run). An idle panel lapses the token, so the first ducks write of a course 403s otherwise. **Refresh = boot a Rise COURSE EDITOR; the SPA rotates the bearer natively.** Operator-confirmed: only a course-editor boot rotates the token — the dashboard does NOT. The headless Okta silent-auth iframe (`/authorize?prompt=none` + `okta_post_message`, still documented in `docs/rise-api-reference.md` §2 as the SPA's own flow) was tried and FAILED at runtime. `reauth()` first re-reads the cookie, then reloads an existing editor; for `GET_COURSE`, if only the dashboard is open it may open the course already being fetched in an inactive temporary editor tab, capture the rotated cookie, close that tab, and retry the same read once. The exporter stops the queue after an unrecoverable auth failure instead of repeating it for every course. `lifecycle/refresh` is ONLY a `204` SSO keep-alive (never gate on it). A refresh counts as real **only when `exp` advances**. (`TODO(refresh)` in `entrypoints/background.ts`: revisit a no-reload silent path.) See `docs/rise-api-reference.md` §2 + §12. Never persist customer credentials.
- **Course creation handshake (mirror the editor).** A single `POST /manage/api/content` creates a FULLY-MATERIALIZED course (capture-confirmed: `GET_COURSE` returns it `200` immediately, with the classic theme + a random built-in cover; a bare titleless/lessonless shell is valid). Immediately after the POST, **always `GET_COURSE` the new id before any write** — exactly as the editor does on open — to confirm the shell is real. If it doesn't return a `course`, abort building on it. **Destructive operations require operator confirmation.** Editing envelopes that mutate or delete content (`DELETE_BLOCKS`, `DELETE_LESSON`, `MOVE_BLOCKS`, `BULK_UPDATE_BLOCKS`, `UPDATE_BLOCK_DEBOUNCE`, `UPDATE_LESSON_ORDER`, `DUPLICATE_LESSON`) are protocol-available but **never fire without explicit operator approval**: the panel shows the full changeset (created / updated / deleted / unchanged counts, per-item detail, deletions highlighted) and waits for confirmation before any write envelope is sent. Course-level `softDeleteContent` stays unused — course deletion is out of scope. An orphaned/never-confirmed course shell is reported and left in place for manual cleanup. (A `GET_COURSE`-404 / `content/search`-500 phantom comes from a *partial delete*, NOT from creation — keep that for reference; do not build phantom-repair.) Preserve the source `course.type` (e.g. `onePage`) on the create call — and a **`onePage` shell ships WITH one pre-created empty lesson** (capture-proven; regular/`aiOutline` shells are lessonless): the importer ADOPTS it as lesson 1 (no `CREATE_LESSON`, no rename — a microlearning lesson has no title by design), never creates a phantom second one. Failures: a confirmed course that fails mid-build is **kept** (never auto-deleted); the Stop button halts between plan steps and likewise keeps the partial course; the run ends with a summary of imported / partial / stopped / failed / not-started + ids needing manual cleanup. **Resume is per-RUN at COURSE granularity, not per-step:** a re-run reads each course's `_import/<id>.report.json` and SKIPS courses already imported (delete the artifact to force), but a course that failed or stopped mid-build is re-imported **from scratch as a NEW course** — there is no step-level resume, so the earlier partial must be deleted by hand. **No title markers (operator decision 2026-08-04):** the clean title is written ONCE, as soon as the first lesson materializes the course; partials are identified via the run reports / read-back / a manual export-from-target pass, never via `!importing:`/`!unfinished:` renames (that machinery is gone).
- **IDs:** course id and lesson id are server-assigned; block ids and item ids are client-generated (cuid-style) — generate consistently and keep internal `refs` (`items:<itemId>/…`) valid. **Never trust a source client id to be unique:** real courses (Rise's own samples) number blocks/items `"1"`,`"2"`,`"3"` and REUSE those ids in every lesson, so shipping them verbatim makes the server clobber blocks across lessons (and, on a stack, silently drop their l10n cells). `freshClientIds` re-mints every non-cuid block/item id positionally + per block (leaving nested `meta.slides[].id` / bank `questions[].id` alone), and everything addressing a source block is keyed by **lessonId+blockId** (`blockKey`), never blockId alone.
- **Multi-language stacks (`docs/rise-multilang.md`) — full-course-first ("idea 2", v0.6.7).** A stack is ONE course whose doc is l10n-ified: `{l10nId}` refs + per-locale cell tables in `payload.l10n` (most media keys live IN the tables; cells may exist in any subset of locales; render falls back locale→default→any). Detect via `isLocalizedStack` (`core/l10n`). Import = **build the FULL course in the DEFAULT language** from the materialized doc (the monolingual path: plain titles, plain values, media uploaded, clean title + description pre-conversion), then **convert ONCE per formality group** (`POST …/translations` — the ONLY way to create locale rows; the AI translates the real content and, decisively, **stamps `translatedAt` on every cell**, so a migrated stack pends nothing — badge 0), then **pair every source ref to the target's own refs structurally** (`core/l10n/pair.ts`: course fields by path, lessons via the id map, blocks via the minted client ids — no source l10nId ever ships) and **overwrite every TARGET-locale row from the archive** via bare `UPDATE_L10N_BATCH` updates — **substantive content is never left AI-translated where the source has a row**. The write-order invariant, idea-2 form: **all default-locale content exists BEFORE the conversion; after it, never write a default row** (it would re-pend the cell in every locale under the US `translatedAt` rule). Title/description cells for every target locale are fallback-resolved (D2 — the target displays what the source displays); known residue: the conversion's AI text persists in default-only TEXT cells (source falls back there) — predicted (`defaultOnlyTextCells`) + listed in the report. Pending is verified as a SET via `GET …/translations/updates` (never counts — `pendingChangesCount` is lazy, `updateCount` is a segment tally); expected set after import: EMPTY, so "Update translation" finds nothing to do. **Stack web export/publish is Localize-subscription gated** (`build/raw` → HTTP 500 without it), so a stack's **Storyline embeds can only be staged from a subscribed account**; the default language's package attaches pre-conversion like a monolingual block, other languages via post-conversion cell writes (flagged if the conversion did not l10n-ify the slot).
- **EU-resident store** for the US→EU case. The archive is a folder the operator picks and manages directly (no purge action: deleting the folder + "Forget" is the purge); extension-local state is only the session token, job artifacts, and the folder handle.
- **Service worker is ephemeral, and the ORCHESTRATOR RUNS IN THE PANEL.** The SW only relays individual requests (so it must never hold run state: restore-from-`storage.session` is awaited, long socket waits are kept alive, and every message path answers even on a throw). The paced loops, plan execution and FS writes live in the side panel — **the panel's lifetime is the job's lifetime**: closing it kills the run. Job artifacts are persisted per course so a re-run resumes at course granularity (see the creation-handshake invariant).

## Storage
- Course archives → File System Access API into a user-picked folder. Layout: root = `manifest.json` + content dirs `courses/`, `question-banks/`, `assets/` (content-addressed); raw account source in `account/` (folders, block-templates, typefaces); derived reports (inventories/census/catalog/novelty/assets-summary) in `_metadata/`. See `docs/rise-account-exports.md` for the full account export map.
- App state (registry, job status, session/identity) → `chrome.storage.local` / IndexedDB.
- All storage behind a `Storage` interface: `FileSystemStorage` now, `DbStorage` later.

## Conventions
- Asset/cross-ref discovery is a **generic recursive scan** of the full document, not a per-block-type walk.
- Dedup binaries by content hash: upload once, reuse the key for all references.
- **Every repeatable action shows `[i/N]` progress.** Any loop that does N units of work (folders, fonts, banks, lessons, courses, blocks, assets, purges, deletes…) logs per-item progress in the same form — e.g. `[3/20 folders] OK created "Name"`, `[12/77 fonts] OK created typeface "X"`, `[1/5] course …`. Never run a long loop that looks frozen; the operator must always see which item N-of-total is in flight.
- Keep this file under ~200 lines.
